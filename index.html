A test site for the Umerang Metrics & Events Catalog. What you do on this page sends real events to the Umerang collector on staging (merchant UTA7F4D868). The event log shows every batch that was sent.

How to test

  1. Use a section below. Each one lists the catalog events it covers.
  2. Open the event log to see each batch the collector sent, decoded, with its HTTP status.
  3. Check the Umerang dashboard for the same events. A chip turns green once its event has been sent successfully.

Section 1.1 · 1.2 — auto-captured

Page views, navigation and clicks

The catalog says the collector captures these by itself. Load the page, scroll, switch tabs and click around, then check the log.

Sent by: the collector's auto-capture. With the toggle on, this page also sends them. The collector reports button clicks as button_click, which is not a catalog name.

session_start · page_viewFire when the page loads. Reload for another page view. A new session starts after 30 minutes idle.
page_view_endSent when you leave or reload the page. It goes out while the page is closing, so it can't show in this page's log; confirm it in the dashboard.
scrollScroll to 25, 50, 75 and 100%. The bar at the very top shows how far.
visibility_changeSwitch to another browser tab, then come back.
navigationUse the section links in the top bar.
element_viewThis card has the data-track-view attribute, so it counts as viewed once half of it is on screen.
printOpen the print dialog. Cancelling is fine.

Section 1.2 — search

Site search

Searching reloads the page with ?q= in the address, like most store searches. Click a result to fire search_result_click.

Sent by: the collector's auto-capture. With the toggle on, this page also sends them.

Section 2.1 — products

Shop

Products fire product_impression as they scroll into view. Open one to fire product_click and viewed_product.

Sent by: this page, with umerang.track() and the catalog's field names. Pressing a Wishlist button also makes the collector send its own add_to_wishlist.

Section 2.2 — cart

Cart

Change quantities, apply SAVE10 or TEST20, then check out. cart_view fires when this section comes into view.

Sent by: this page. Pressing Checkout also makes the collector send its own checkout_started. cart_abandoned and cart_recovered are backend events; see the list at the bottom.

Section 2.3 · 2.4 — checkout and order

Checkout

Three steps. Leave fields empty to trigger checkout_error. Test mode: no payment details are asked for or collected.

Sent by: this page. Order fulfilment, refunds and returns are backend events.

Section 2.5 — subscriptions

Membership plans

Subscribe, move up or down a plan, or cancel.

Sent by: this page. The Subscribe buttons also make the collector send its own subscribe event. subscription_upgrade sends the field upgrDelta, spelled as in the catalog.

Section 3 — customer identity

Account

Sign up or log in first. That calls umerang.identify(), so later events carry your email and customer ID. Use test details only.

Sent by: this page, with umerang.identify() and umerang.track().

Section 4 — custom events

Custom merchant events

Send any merchant-defined event with umerang.track(). Pick one of the catalog's examples or type your own name.

Sent by: this page. Names must start with a letter and use only letters, numbers, _ or - (up to 64 characters), or the collector drops them.
